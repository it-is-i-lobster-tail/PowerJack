Branch: enhancement/clarify-locked-workout-copy
Date: 2026-06-24

Why was the branch needed:
Future locked workouts showed the generic `Read-only` chip, which did not tell users why the next workout could not be edited. PJ-33 requested clearer copy that tells users to finish the current workout first while leaving completed workout copy unaffected.

Outcomes of code changes:
The workout header now shows `Finish current workout first` for locked future workouts and keeps `Read-only` for completed read-only workouts. The start-flow E2E coverage now asserts the new future workout copy while preserving the existing completed workout assertion.

Implementation decisions that were made:
The UI keeps the existing lock icon, chip styling, and `data-agent-id` selector. The copy condition treats locked active or planned workouts as future locked workouts because same-week future days can render as locked before activation, while completed, halted, and skipped read-only states keep the generic read-only label.
