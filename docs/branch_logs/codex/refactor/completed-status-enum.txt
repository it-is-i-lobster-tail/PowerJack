Branch: codex/refactor/completed-status-enum
Date: 2026-06-23

Why was the branch needed:
The shared PowerJack status enum used the persisted value complete for completed programs, workouts, lifts, and sets. The requested change was to make the status value grammatically consistent as completed everywhere it is part of the enum or status-backed UI, while preserving ordinary action copy such as Complete every set.

Outcomes of code changes:
The domain status union, program list filters, program overview status counts, workout completion logic, analytics queries, repository SQL, in-memory repository behavior, E2E selectors, and visible program status labels now use completed. Existing local SQLite data is migrated from complete to completed, CHECK constraints reject the old enum value, and affected indexes and related rows are preserved.

Implementation decisions that were made:
The released initial migration was left unchanged and a new numbered migration was added. The migration rebuilds programs, workouts, lifts, workout_sets, feedback, and app_state so foreign keys remain coherent across web SQLite while the status tables are swapped. Focused sql.js migration coverage was added to verify old-value conversion, CHECK enforcement, index recreation, feedback preservation, app_state preservation, and foreign-key health.
