Branch: codex/enhancement/completed-set-stats
Date: 2026-06-23

Why was the branch needed:
PowerJack's data visualization and program detail screens need faster completed-set muscle-volume queries. The existing SQLite analytics repository derived primary and secondary muscle credits at read time by joining completed workout sets through lifts, exercises, and secondary muscle tables, which made common date and program filters more expensive than necessary.

Outcomes of code changes:
The database now has a completed_sets_stats table that stores one live stats row per completed workout set with fixed muscle-credit columns. Completing a set inserts the row once, re-saving a completed set preserves the original row, clearing a set removes it, and deleting workout sets cascades the stats row. Training analytics now reads from the materialized table while keeping the existing domain-facing CompletedSetEvent interface stable.

Implementation decisions that were made:
The table uses workout_sets as the set source, set_id as the primary key, and forearms as the fixed column name to match the seeded muscle catalog. The migration is schema-only because this is pre-alpha and local databases are rebuilt frequently. A shared infrastructure mapping keeps the stats columns aligned across insert and query code, and sql.js-backed tests cover migration constraints, uniqueness, clearing, cascade behavior, and analytics event expansion.
