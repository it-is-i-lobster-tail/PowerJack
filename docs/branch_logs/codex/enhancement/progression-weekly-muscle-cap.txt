Branch: codex/enhancement/progression-weekly-muscle-cap
Date: 2026-06-23

Why was the branch needed:
The lift progression system could continue adding volume sets based on lift-level eligibility even after the user had already reached 25 credited sets for a muscle group in the prior program week. The requested behavior was to stop set additions at that weekly muscle cap and fall through to normal load or rep progression instead.

Outcomes of code changes:
Progression now receives previous-program-week muscle set credits and checks the projected primary and secondary muscle credits before applying focus or non-focus volume gates. SQLite and in-memory week generation both calculate prior-week muscle credits from completed logged sets, and the new progression documentation explains the decision order, volume eligibility, weekly cap, load progression, and rep progression in plain English. The root README now identifies that document as the progression source of truth.

Implementation decisions that were made:
The cap reuses the existing analytics credit model: primary muscles count as 1 set and secondary muscles count as 0.5 set. The cap is applied only to volume gates, so cap-blocked lifts keep the existing load or rep gate rather than introducing a new public gate. Tests cover primary cap blocking, secondary cap blocking, exact-cap allowance, in-memory generated weeks, and sql.js-backed SQLite behavior.
